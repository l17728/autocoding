# 开发计划与需求追踪

## 阶段与交付门禁

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| M0 设计基线 | 需求、架构、SDD、用例、日志、适配调研、PM 话术、独立专家审阅 | 阻断级意见关闭；未验证外部能力有明确门禁 |
| M1 可靠核心 | SQLite 账本、任务依赖/领取、幂等、完成验证、输入权、审计及离线演示 | 核心故障测试通过；演示明确为模拟，不宣称模型接入 |
| M2 真实会话 | 三适配器、智谱连接、能力探针、ConPTY 原型 | 各 Agent P/E 证据，文本/权限/中断/恢复实测 |
| M3 可视协作 | 本地工作台、终端、PM 对话、接管、状态与诊断 | 三实例同时可见，UC-05/06/12/14 通过 |
| M4 自主项目 | PM 决策、MCP、知识视图、协调、集成与验收 | 小型真实项目从需求到验收，故障恢复通过 |

首个产品版本包含 M1 到 M4 的必要范围，M1 只是启动开发的首批成果。阶段门禁限制“通过”声明，不限制开发其他不依赖该能力的模块。

## 实现状态记录原则

实现进展记录在仓库 README 和测试结果中。每项用 not_started/in_progress/unit_verified/local_probe_verified/live_verified/blocked 标注；unit_verified 不能简写成支持供应商。当前可用性受到网络与凭据读取限制时，完成离线核心、探针和配置解析测试，保留明确集成缺口。
