# 开发协作平台用例与验收规格

## 测试层次与数据

单元测试覆盖领域约束；SQLite 集成测试使用临时磁盘数据库和两个独立连接；协议测试使用可控 fake Agent 重现断线、乱序、重复事件、半包 JSON；实机测试才可确认供应商兼容性。fake 通过不得代替实机通过。

基准项目 fixture 为不含真实凭据的小型 Git 仓库，包含一个计算模块、一个必失败测试、一个依赖任务、一个故意冲突的分支。会话测试文本同时含中文、emoji、CRLF、多行和类似 shell 的普通文字。破坏性故障注入仅针对测试子进程与临时目录。

## 主流程用例

| ID | 前置与动作 | 预期结果与证据 |
|---|---|---|
| UC-01 导入需求 | Owner 选择 DOCX/Markdown；PM 提取 FR 与验收项 | 每个需求可回到来源章节；不明确项列出，不编造已确认条件 |
| UC-02 任务规划 | 建实现/测试任务并建立依赖；另提交一个环 | 正常 DAG 入库，环整次事务拒绝；保留 DecisionRecorded/TaskCreated |
| UC-03 注册 Agent | 分别探测三种 CLI，并模拟缺失可执行文件 | 显示版本、可用能力及证据；缺失实例不可领取任务 |
| UC-04 隔离工作 | 两实例同时编辑同名文件 | 各自 Worktree 内容独立；日志含 cwd、branch、base SHA |
| UC-05 发出指令 | PM 发中文多行输入；用户另发相同内容但不同键 | 同键同请求只建一次命令，不同键允许新命令；每条目标 session 固定 |
| UC-06 可视交互 | 同时查看三实例；切换卡片与 resize | 输出互不混流；模式明确；首字符到 UI 延迟可测；断流显示缺口 |
| UC-07 持续调度 | A 完成解锁 B，无任务时保持空闲 | B 验证依赖后派发；没有工作时不循环请求模型 |
| UC-08 质量返工 | Agent 声称成功但测试失败；修复后再报 | 首次转返工且附明确失败证据，下一 attempt 复验通过才 done |
| UC-09 协调冲突 | 两 Agent 对接口签名不一致 | PM 收集意见，记录决策、替代关系及落实任务；不直接改业务文件 |
| UC-10 知识刷新 | 修改实现后查询旧模块索引 | 依据 SHA 标 stale，刷新或显式返回旧版本，不默默当最新 |
| UC-11 重启恢复 | 输入发送后、确认前终止宿主并重启 | 命令为 delivery_unknown；无自动双发；对账结果含因果链 |
| UC-12 人工接管 | PM 命令排队时 Owner 接管，随后归还 | 旧 epoch 排队命令取消；人工文字只进入目标会话；归还含摘要 |
| UC-13 权限处理 | 收到文件/命令权限请求，用户拒绝或过期 | 仅匹配 request_id 被响应；拒绝不转成自动同意；任务显示阻塞条件 |
| UC-14 问题定位 | 给出一次失败的 command_id | 诊断包找到上下文、输入摘要、发送/响应、错误、版本、测试证据 |
| UC-15 风格学习 | 读取授权历史，并放入带密钥与恶意指令样本 | 只产生风格规则；凭据和项目私有内容不进入模板；历史内容不能覆盖权限 |
| UC-16 Claude 智谱 | 配置凭据引用和已验证端点，执行无副作用问答，再试错误 key | 成功有 provider/model/session 证据；401/403 脱敏且不重试刷请求 |
| UC-17 集成验证 | 合并两个分支，其中一个产生冲突 | 冲突生成协调任务；合并后在新 SHA 验证，旧测试结果不沿用 |
| UC-18 最终验收 | 全部需求有证据，Owner 接受或拒绝 | 接受才项目完成；拒绝转成有来源的修正任务并保留历史版本 |
| UC-19 本地服务控制 | Owner 从桌面控制器启动、检查、打开和停止工作台 | 仅在 `/health` 就绪后显示运行并打开首页；停止前核对登记 PID 的工作台命令行；端口被未知程序占用时拒绝接管 |

## 必测异常与竞态

| ID | 注入方法 | 必须满足的不变量 |
|---|---|---|
| FT-01 双领取 | 两连接同时 claim 同一 ready 任务 | 恰好一个租约成功，另一个 409；只有一条成功派发事件 |
| FT-02 幂等冲突 | 同一 key 改变 payload | 返回 IDEMPOTENCY_CONFLICT，不改变原任务/命令 |
| FT-03 旧租约报告 | 到期、重新对账后旧 Agent 报告 | 拒绝状态推进，记录 STALE_LEASE，保留排障信息 |
| FT-04 迟到输出 | 新 generation 启动后收到旧事件 | 旧事件仅归档，不改变当前会话 |
| FT-05 重复完成 | 同一次供应商 completion 重复两次 | 只创建一次验证工作 |
| FT-06 接管竞态 | 发送前检查后与写入之间请求接管 | 输入串行锁定义顺序；已发送不宣称撤回，未发旧 epoch 不发送 |
| FT-07 队列阻塞 | 慢消费者、输出每秒 10 MiB | 读进程不因 UI 阻塞死锁；有限内存，写盘/背压/缺口事件明确 |
| FT-08 文本攻击 | 输入含换行、引号、$()、ESC、OSC52 | 不执行 shell 展开；控制序列独立通道；终端剪贴板/链接能力受限制 |
| FT-09 凭据泄漏 | stderr 回显 key、Bearer、URL query token | 日志与诊断均脱敏；测试包含多块切分的密钥 |
| FT-10 存储耗尽 | 降低磁盘配额或模拟 SQLITE_FULL | 停止新派发并显示诊断，不能已执行而未记账还报告正常 |
| FT-11 审批重放 | 重放已批准或过期审批 ID | 拒绝；审批不跨 session/generation 使用 |
| FT-12 路径逃逸 | ..、符号链接、Windows junction | 不能读写项目授权根之外交付物 |
| FT-13 长测试静默 | 持续心跳但 10 分钟无 stdout | 标识运行中，不因静默认定失败 |
| FT-14 重启事务边界 | commit 前后/发送前后逐个崩溃 | 事务前无效果，事务后事件可重放，外部发送不确定明确暴露 |
| FT-15 手动输入暂停 | 未握手完成就输入或暂停中发送 | 指令排队或拒绝；不混入认证提示/密码框 |
| FT-16 中文与 resize | 不同 DPI、80/120列、中文/emoji 输入 | 无乱码、错位可复现并记录终端尺寸；真实 TUI 手工检查 |
| FT-17 网络恢复 | SSE 游标落后于保留窗口 | 410 后拉快照接续；不遗漏当前状态、不无穷重放 |
| FT-18 无模型输出 | 供应商进程退出 0 但没有完成/结果事件 | 仅进程正常退出，不能算业务成功 |
| FT-26 本地服务误停止 | 状态文件过期、PID 已复用或 8765 被其他程序监听 | 不按端口强杀；命令行不匹配时保留状态并报告；启动拒绝占用端口 |

## 验收记录格式

每次记录 test_id、build/version、OS、fixture SHA、adapter/version、mode、步骤、expected、actual、pass/fail/blocked、trace_id、日志附件及测试人。机密输入用引用替代。自动测试报告保存 JSON/JUnit；真实 UI 验收保存脱敏截图或视频索引。实机测试因账号/网络受阻应写 blocked，不写 skipped 后计入通过率。

完成 FR-03/05/06/11/12/13/16 必须各有三种 Agent 的适用项矩阵；供应商不支持的功能经明确降级设计验证后记录限制，不能只用统一 mock 覆盖。


## 专家审阅新增故障用例

| ID | 场景 | 预期 |
|---|---|---|
| FT-19 | claim/report/command 事务成功后丢失响应，状态随后推进，再以原 key 重试 | 认证后先查幂等记录，返回原结果；不同 payload 拒绝，不增加业务事件 |
| FT-20 | 验证中取消任务，或变更需求/验收，再收到旧 verifier 结果 | revision/acceptance hash/job ID CAS 失败；取消/失效状态不变；旧证据仅归档 |
| FT-21 | 底层发送永久阻塞，同时 Owner 请求接管 | 5 秒后 unknown/reconciling；旧发送未确认停止前无新输入，界面说明等待原因 |
| FT-22 | 读取快照时另一个连接持续写事件 | snapshot 与 latest_seq 同事务，接续 > seq，无状态遗漏或重复应用 |
| FT-23 | 审批相同 request_id 跨会话/代际复用，或回传前崩溃 | 复合身份隔离；原决定落盘后可恢复，未知回传不变造新请求重放 |
| FT-24 | 租约过期但旧进程/远端任务仍运行 | 保持 reconciling，不重用旧工作区、不自动重新领取 |
| FT-25 | 所有持久化通道写入跨块敏感金丝雀 | JSONL、events payload、会话分片、诊断包均无明文；原始/脱敏偏移不混淆 |

DEV-02/03/04/05 分别承担 FT-19/24、FT-19/21、FT-20、FT-22/23；FT-25 由 DEV-15 与各持久化模块共同验证。M1 没有实际 Runner 的 FT-21/24 只能验证禁止重派发守卫，真实进程阻塞/退出证明由 M2 实机测试完成。
