## 运行与安全边界

- Core 和 stdio MCP 是可信本地进程接口，actor 字符串本身不是认证。网络 API 仅监听 127.0.0.1，通过 Owner 令牌认证；尚不适合公开部署。
- 工作台仅启动原生可执行文件，不经 shell 拼接模型输入。真实模型调用会消耗账户额度。Claude 文件/命令工具仅对显式注册的工作树开启，按用户要求使用 `--dangerously-skip-permissions`；Codex 使用 `danger-full-access`。这些设置不会隔离当前用户的文件权限。独立验证和提交前的受保护文件检查不能阻止此前的命令副作用。
- 对仍由协议发出的权限请求，PM 可批准、拒绝或交用户，绑定操作哈希、会话代次、版本和过期时间。OpenCode 只回复 `once`，不自动设置永久许可。结构化问题支持选项和自定义文本；秘密输入不交 PM 自动填写。原生 TUI 任意弹窗尚未自动化。
- 审批原始操作保留在进程内供用户审阅；账本存储哈希。审批发送中断或崩溃后保持未知，不自动批准或重发。
- 启动会话、创建工作树、PM 草案/采用和中断使用持久操作意图。结果已保存可重放；发生效果但未保存结果的窗口要求对账，避免重复执行。
- ConPTY 输入为 sent_unconfirmed，屏幕回显不会推进模型回合或开发任务完成。接管后无法证明执行结果的输入保持冻结。浏览器支持直接键盘、常用控制键、缩放、关闭和手动恢复，尚无任意 TUI 弹窗自动处理。普通无换行提示即时输出，疑似凭据前缀继续缓冲脱敏；超长敏感片段丢弃后持续抑制至分隔符，输出窗口有界并提示缺口。
- 验证/终端工作进程采用 Windows Job Object 管理本地后代；供应商远端模型停止没有证明。不能混为一谈。
- 验证器清理子进程环境中的模型凭据，并只保存输出字节数/哈希。它不是恶意代码安全沙箱，测试进程仍具有当前操作系统用户的文件权限。
- Git 操作不使用全局配置、禁用钩子且不继承模型 key 环境。工作树删除必须显式标记已停止且干净，不使用强制删除。集成只生成可审阅候选，不发布、不修改主分支。
- PM 模型自身不开放 shell，负责任务草案及问题/权限判断；执行器可按选定计划自动运行 Claude。模型不能自行标记任务 done，必须独立验证通过。采用时检查原任务上下文并验证 DAG。PM 可能误判；信息不足或超出范围时转用户。知识内容始终标记为参考材料。
- 协议恢复绑定明确 provider session ID 和原存储目录，进程异常最多自动恢复两次。终端恢复复用原工作树与原状态目录，只有已确认停止的实例可手动续接，不自动重启、不重放未知输入。终端保存停止标记和后继实例，未确认停止的崩溃实例不能恢复。平台重启后非终态任务/批次冻结等待对账。
- `.local/credentials/opencode.json` 为本机明文配置，已被忽略提交；未修改全局 Claude 设置，未声称 DPAPI 加密成功。令牌和模型 key 不输出到控制台。
