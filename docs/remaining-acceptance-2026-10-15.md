## 本轮改动

- SQLite 写入故障：实际触发容量上限、只读数据库、写锁争用；核对任务、事件和幂等记录整体回滚，数据库完整性正常，恢复后同键只创建一次。容量上限使用一次性数据库的 `max_page_count`，不填满本机磁盘。
- API 把 SQLite 故障转为脱敏的 HTTP 503，并禁止客户端自动重试；页面提示核对结果。服务生命周期保持无事务的连接，减少 Windows 下最后连接关闭引起的 WAL 重建与检查点开销，未降低同步持久化等级。
- 真实 ConPTY + Node 原始输入测试逐字节验证 ST/BEL 终止的颜色回复；前后端补齐 OSC 12 白名单。移除尚未实现的 Kitty 键盘协议声明。
- 原生 Codex 实测发现 OSC 10/11 颜色回复被解释为键盘输入，ESC 中断模型回合、余下字符进入提示框。完全停止颜色回复、每个进程仅回复一次的实验分别未通过启动/画面验证，均已撤回；此缺陷未解决。
- OpenCode 原生会话复用协议适配的私有用户目录隔离，恢复继续使用原目录。没有升级或修改本机供应商程序。
- 增加有界的真实 Codex 多项目开发探针，以及原生 Codex 关闭/续接的随机上下文验证。探针不以提示词回显证明模型作答。
- 终端入口明确提示 Codex 控制字符干扰、OpenCode 空屏这两个已确认缺陷，并指向协议会话卡或任务执行入口；仍允许显式启动原生终端，不把它作为开发验收成功的依据。
