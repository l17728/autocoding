# 开发协作平台需求规格

## 目标与边界

用户提出需求后，PM 组织多个开发 Agent 完成设计、实现、测试、审查和交付。用户能在一个本地工作台看见每个工作区收到的文字、Agent 回复、工具执行、权限请求、测试结果和后续调度，也能暂停、接管和恢复。所有结果可由任务定位到运行日志与具体提交。

第一目标平台为 Windows 10 1809 以上或 Windows 11，启动时检查 ConPTY 能力。单机、单 Owner、多项目；默认同时运行 3 个执行 Agent，最大并发可配置。远程多人协作、游戏、通用电脑操作、人格微调、无人审批部署、自动付费采购均不在首版范围。

## 功能需求

| 编号 | 必须实现的行为 | 验收依据 |
|---|---|---|
| FR-01 | 导入需求文档，产生有来源章节、验收条件与版本的需求条目 | UC-01 |
| FR-02 | PM 将需求拆成带依赖 DAG、明确交付物及验收条件的任务；拒绝环和不存在的依赖 | UC-02 |
| FR-03 | 注册 Codex、OpenCode、Claude Code 实例，记录实际版本与能力；未配置项不可伪装在线 | UC-03 |
| FR-04 | 每个执行实例使用独立 Worktree/分支；显示当前目录、分支和提交 | UC-04 |
| FR-05 | 从 PM 或用户发送多行中文指令；保留发送者、目标会话、命令 ID、原文摘要与发送状态 | UC-05 |
| FR-06 | 可视工作区显示真实终端或明确标识的协议会话；区分排队、已发送、已接受、执行中、完成 | UC-06 |
| FR-07 | PM 依照就绪任务、能力、预算和负载持续调度；没有任务时等待事件，不空转消耗模型 | UC-07 |
| FR-08 | Agent 完成后提交证据；验证失败进入返工，执行结束不能直接将任务标为完成 | UC-08 |
| FR-09 | 组织跨 Agent 协调，保存参与意见、决策依据、被替代决策及落实任务 | UC-09 |
| FR-10 | 维护 Owner 需求/质量/进度视图与 Dev L1/L2/L4 知识；L3 自动代码解析后续实现 | UC-10 |
| FR-11 | 断线、进程退出、应用重启后恢复账本；状态不明的输入禁止盲目重发 | UC-11 |
| FR-12 | 人工接管撤销 PM 输入权，暂停只影响选定范围；保留会话后可继续 | UC-12 |
| FR-13 | 权限请求展示原始操作、范围、有效期；批准仅用于对应 request_id | UC-13 |
| FR-14 | 完整关联操作日志、结构化事件、终端记录、错误与诊断包 | UC-14 |
| FR-15 | 从授权的本机历史用户指令提取通用协作风格；不复制其他项目实现或凭据 | UC-15 |
| FR-16 | Claude 可选择智谱 Anthropic 兼容连接，模型与 OpenCode 中选择一致；密钥运行时引用 | UC-16 |
| FR-17 | 手动合并或指定集成 Agent 合并，基于合并后提交验证；冲突不能静默覆盖 | UC-17 |
| FR-18 | 项目验收报告包含需求覆盖、测试证据、已知缺口，Owner 接受后项目完成 | UC-18 |

“完整可见”指全部可呈现的输入、输出、工具动作和授权事件，不要求模型内部推理。原生 TUI 和协议事件视图要有可辨识的模式标签，不能把渲染的聊天记录称为原终端截图。

## 非功能指标

| 编号 | 指标与测试口径 |
|---|---|
| NFR-01 一致性 | 同一任务同一时刻最多一个有效租约；同一幂等键同请求重放返回原结果；同键异请求报冲突 |
| NFR-02 可恢复 | 已提交事件不得丢失；进程重启 10 秒内完成本地账本扫描，外部会话对账不计入且显示进度 |
| NFR-03 响应 | 本机 3 实例、每秒 30 条结构化事件、10 万历史事件下，命令入队 p95 < 200ms，界面新增文本 p95 < 500ms；不含模型响应时间 |
| NFR-04 限额 | 单条用户输入 64 KiB UTF-8，单帧事件 1 MiB；每会话显示缓冲 10 MiB，磁盘默认 1 GiB/项目；接近上限告警 |
| NFR-05 安全 | 默认仅回环地址；控制与终端 WebSocket 校验 Owner 会话、Origin、项目和输入租约；不把密钥放命令行或普通日志 |
| NFR-06 可定位 | 100% 命令、状态变化、权限决策含关联 ID；测试能从命令 ID 找到发送、响应或明确的缺失原因 |
| NFR-07 兼容 | 三种 Agent 逐一完成探测、启动、中文多行输入、输出、续会话、中断、错误、权限请求的实际验收 |
| NFR-08 测试 | 状态机/调度/权限/恢复/输入路由分支覆盖率目标 90%，总行覆盖率 80%；阈值与未达项必须展示，不等同于质量充分 |

性能基准记录 OS、CPU、内存、磁盘与版本，不将上述目标写成已测成绩。

## 完成标准

“任务验证通过”需要提交 SHA/补丁摘要、验收条目结果、命令退出码、日志引用和已知限制；独立验证器绑定精确提交，执行 Agent 的自述仅作线索。项目完成还需要在集成分支复验并由 Owner 验收。无凭据、无法联网或适配器仅 mock 通过时，明确标识阻塞/待实机验证，不能降格成通过。

## 本次已确认的变更

支持三种 Agent；允许安装 Claude 并复用本机 OpenCode 智谱配置；原始 DOCX 与 AGENTS.md 不修改。设计完成后由独立专家代理审阅，关闭阻断问题后启动开发，不另增一次用户确认门槛。
