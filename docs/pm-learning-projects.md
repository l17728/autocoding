# 本地项目配置与 PM 自检设计

## 2026-10-15：规模、故障退避与跨主题候选

知识读取增加 SQLite 修订计数与触发器。自检写入、归档或决议修改使缓存失效；其他 Host 修改同一账本也能被识别。缓存按下一条知识的过期时间失效，系统时间回退时重建。知识引用使用独立缓存，结果复制后返回，调用者不能污染缓存。TaskRunChanged 增加 type/seq 索引，结果窗口按事件最大序号缓存。冷启动或知识变化仍会重新聚合历史记录，不是完整的持久化语义索引。

页面每页 25 个主题，`GET /pm/knowledge?offset=0&limit=25` 支持 1–100 条分页，负偏移被拒绝；`GET /pm/reviews?offset=25` 返回对应知识页。分页边界是主题，不是主题内的版本/来源，极端单主题聚集仍需单独规模验证。

加入版本化代码中的中英文领域别名：测试/验收、权限/审批、未知投递/重放、凭据/API key。单一明确领域下，不同主题、不同类别的建议进入同一候选组，避免仅靠模型生成的主题名称发现不了分歧。混合领域不猜测归属，保留原主题。它是保守的候选筛选，不是通用语义矛盾证明；可能将互补意见列为候选，必须核对后选择。原文和来源不删除。

自动自检连续失败后使用持久化指数退避（基准间隔翻倍，最多增加到 24 小时，原周期超过 24 小时则保持原周期），成功清零。手动自检仍由 Owner 明确触发。原证据游标在失败时保留，未知输入不重放。

规模工具：`python tools/learning_soak.py --records 5000 --seconds 300`，使用隔离账本及合成知识，不调用模型。检查分页、引用上限、结果窗口、每 60 秒重建 Host、操作 p95 与 Python 跟踪内存；报告写入 `.local/learning-soak-*/report.json`。可调持续时间，但数分钟结果不能替代 24 小时演练，也不覆盖供应商、真实用户多并发或完整进程崩溃。

模型账户诊断：HTTP 429、业务码 1310。依据 [官方服务错误码](https://help.aliyun.com/zh/model-studio/glm-zhipu)，该码表示周/月使用上限。程序不能解除账户配额，恢复真实链路需额度重置或账户侧恢复可用额度；不以替换到未知账户或重复请求绕过。诊断只保存数值错误码与分类，不打印 key 或响应正文。

## 2026-10-15：知识治理与效果观察

新增 `learning.py`，对全部已完成且未归档自检建立可重算的知识视图，不再因记录离开最近 50 条页面而遗忘知识。按类别、稳定 topic 分组；内容经 Unicode NFKC、大小写和空白归一化后去重，保留每条来源。旧记录没有 topic 时以内容作为主题，兼容旧账本。不会删除原始总结。

同主题不同建议全部暂停自动引用，页面可选择采用项；其余版本标为 superseded。选择保存组修订摘要并写入审计，新来源或新版本出现后旧选择失效，重新检查分歧。超过 90 天没有新来源的版本标为 expired，不进入后续 PM 上下文。归档排除对应来源；PM 的知识注入记录 `PMReviewKnowledgeUsed`，stage=selected 仅表示已选入待发送上下文，不代表供应商收到、模型采用或产生因果效果。

去重目前覆盖归一化后相同文本，冲突检测覆盖同主题不同建议；语义近似重复、不同主题的隐含矛盾不能保证识别。不同建议可能互补，因此暂停引用后由 Owner 选择，避免模型擅自将合法经验永久删除。知识决议接口为 `POST /api/v1/projects/{id}/pm/knowledge/{group_id}/resolve`，请求包含 selected 和 revision，沿用 Owner 认证与幂等键。

效果面板使用审计中的 TaskRunChanged 结果，按 run_id 去重，首次终态事件确定窗口位置，后续状态修正更新结果但不重复计样本。最近 20 次与之前最多 20 次执行比较，分数为独立验收 done 次数占比，返工、失败、待对账均计入分母。两个窗口各至少 10 个样本才显示百分点变化；零样本不生成分数。此指标受任务难度、模型和执行环境影响，不等同 PM 能力评分，不证明特定经验有效。

调度器记录心跳及脱敏错误码，遇到运行异常后继续下一周期，取消仍终止。模型自检失败显示异常健康状态。全部知识仍是参考资料，不改变固定核心原则。

生产验收仍需：真实模型自检与知识回用闭环通过；按任务类型建立可比样本和基线，结合知识使用记录评估改善；跨主题语义冲突评测；持久化知识索引/分页及规模压测；多进程调度互斥；故障和长时间运行演练。当前按单工作台进程运行，不宣称已达到生产门槛。

## 项目模型与交互

页面顶部统一提供项目选择、当前项目设置和创建/接入入口。字段为稳定项目 ID、显示名称、本地绝对目录、GitHub owner（用户名或组织）、repository、默认权限策略和配置修订号。GitHub 两个字段同时为空或同时有效；保存使用修订号比较，避免旧页面覆盖新配置。仓库 URL 从字段生成，不保存凭据。

本地目录在注册时规范化，拒绝重复目录、文件路径、文件系统根目录和仓库子目录。允许接入非 Git 目录用于规划；执行任务前要求仓库根目录、有效 HEAD 和干净工作区。现有文件与提交不自动改写。只有显式请求且目录为空才初始化 Git 并创建空提交。

绑定目录不可直接修改，避免任务、工作树、会话上下文和知识来源错位；更换目录应注册新项目。注册上限 20 个，当前是本机单 Owner 模式。GitHub 配置仅关联元数据，远程建库、clone、认证、remote 修改和 push 不在本次范围。

`Projects` 在默认账本保存目录清单，为每个项目创建独立 `Host`、账本、运行状态和经验记录；新项目状态置于默认存储的 `projects/<id>`。项目路由经 Owner/Host/Origin 校验后分派至对应 Host。切换页面重置事件游标、输出和未发送输入；请求进行期间禁止切换，防止异步结果串入另一项目。服务重启恢复目录清单。共享两个 PM 调用槽位限制并发。

## 权限与恢复

默认权限策略是 bypass，可切换 review，设置作用于新启动会话。

| Agent | 默认免确认执行 | 原生终端恢复 | 协议恢复 |
|---|---|---|---|
| Codex | `--sandbox danger-full-access --ask-for-approval never` | `resume --last` 并保留权限参数与原工作目录 | 指定 thread ID |
| Claude | `--dangerously-skip-permissions` | `--continue` 并保留权限参数 | 指定 session ID |
| OpenCode | 私有配置 `permission.*=allow` | `--continue`，复用私有数据目录 | 指定 session ID |

review 模式对应 Codex on-request、Claude manual、OpenCode ask。Claude 托管 MCP 使用严格显式配置，manual 模式不能同时启用禁用 MCP 的 safe-mode。恢复已有会话时供应商可能保留创建时的权限，变更策略后应创建新会话。免权限确认不等于自动回答产品选择题：结构化提问仍由 PM 根据项目上下文选择或填写自定义回答，无法确定则留给 Owner。

只恢复已确认停止的终端；未知投递冻结且不重放。完整 TUI 的三供应商上下文恢复实测仍是独立待办。

## PM 自检与知识

每项目独立 `Reflection` 保存调度设置、审计游标和最近 50 次自检。默认启用，间隔 60 分钟，可设置 5–10080 分钟。后台每分钟检查是否到期，暂停派发时不运行；无新有效活动不调用模型。失败保留记录并遵守调用间隔，成功记录和游标在同一事务提交。进程中断中的自检恢复为 interrupted。

输入包括 PM 审计事件、近期问题回答、任务运行/验收结果和计划，脱敏并限制大小。输出必须为结构化 JSON，最多 8 条，分类为话术、经验教训、核心原则、改进建议，标注 observed/hypothesis 并引用输入中的事件 ID。无来源或错误结构整次拒绝，失败结果不进入知识库。

后续规划和 PM 回答注入最多 12 条未归档经验，标为参考资料。自检调用不注入旧总结，降低循环自证。界面支持查看来源编号、手动触发、修改周期、归档/重新启用。固定原则始终要求独立验收、未知输入不重放，经验不得改变用户授权或验收规则。此机制是基于历史记录积累上下文，不是训练模型权重。

## 接口与验证

- `GET/POST /api/v1/projects`：列出与注册项目。
- `POST /api/v1/projects/inspect`：检查目录，不改写文件。
- `GET/POST /api/v1/projects/{id}/settings`：读取和更新配置，写入检查 revision。
- `GET /api/v1/projects/{id}/directory`：目录与提交基线状态。
- `GET/POST /api/v1/projects/{id}/pm/reviews`：读取与手动自检。
- `POST .../pm/reviews/settings`、`POST .../pm/reviews/{review_id}/archive`：调度与归档。

写入沿用认证、幂等键和项目边界。测试覆盖接入原仓库不变、跨项目隔离、配置重启持久化、CAS、非法字段不创建目录、空目录初始化、自检事件来源/脱敏/归档/调度。Edge 覆盖创建、保存、项目切换与 Git HEAD/文件保留。真实模型探针 `tools/pm_reflection_probe.py` 在原账本的只读副本上运行；本轮 Claude 回执超时，尚未通过真实自检与知识回用验收。
