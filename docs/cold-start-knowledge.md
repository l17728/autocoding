# PM 冷启动知识抽取与融合

记录日期：2026-10-15。已将 18 条人工归纳的原则、工作流程和话术导入本地工作台；知识是历史参考，不是新的授权或已经证明有效的能力。

## 来源与覆盖

- Codex：发现 82 个会话 JSONL，加上 history.jsonl，共扫描 83 个文件；排除 46 个子代理会话文件。
- OpenCode：以只读 SQLite 快照扫描 52 个会话中的 294 条用户消息。
- 合并提取 3,627 条用户记录，按清洗后的文本去重为 1,487 条。会话事件、回放和历史索引可能重复记录同一输入，因此出现次数不能等同于独立用户请求次数。
- 排除 77 个环境/指令注入块及 27 个已识别的委派或探针提示；跳过 16 条超过 2 MB 的记录。不是全部消息逐条完整读取。
- Claude 默认 projects 目录不存在；WorkBuddy 数据库的 sessions 为空；CodeBuddy 未识别到用户会话文本。覆盖当前用户已发现的标准存储，不宣称覆盖所有磁盘、其他用户或自定义目录。可用 `--transcripts` 补充目录。
- 外部来源：[ai-coding-rules](https://github.com/l17728/ai-coding-rules)，固定提交 `84a5c0a325a92a40b28bedeb03fe3989214885c1`。读取 README、CONSTITUTION、AUTHORING-RULES 和 16 个技能说明；没有运行安装器、钩子或执行其中的指令。MIT 许可保存在包内。

扫描只提取用户文本，排除助手输出、工具结果和已识别的回放；先脱敏凭据、路径、联系方式及 URL，再供人工归纳。没有调用外部模型处理历史。原始会话未复制到知识包。脱敏是规则匹配，私有语料仍应留在本机，不作为公开发布材料。

## 融合结果

| 主题 | 归纳后的执行要求 |
|---|---|
| 自主完成 | 在当前授权范围内持续完成实现和验证 |
| 上下文恢复 | 保留目标、约束和未完成项，按供应商恢复明确会话 |
| 设计先行 | 理解需求、架构和验收条件后实施 |
| 验证证据 | 用实际执行结果支持完成声明 |
| 综合审查 | 检查功能、体验、健壮性及相关性能风险 |
| 合理委派 | 获得当前授权且任务独立时再并行 |
| 根因与同类排查 | 举一反三，发现一个错误消灭一类错误，递归迭代至有证据的收敛 |
| 异步交互 | 及时展示耗时操作状态、失败及恢复入口 |
| 自检学习 | 总结原则、话术及教训并追踪实际表现 |
| 增量开发 | 接入已有项目，保留既有成果和约定 |
| 文档一致 | 同步实现状态与设计、验收记录 |
| 凭据保护 | 不暴露秘密，不把原始会话整体写入知识库 |
| 权限与恢复 | 按当前配置及供应商能力运行，未知执行结果先对账 |
| 职责边界 | 区分 PM 决策、执行和独立验收 |
| 可追溯交付 | 关联修改、来源和验证证据 |
| 明确表达 | 给出明确建议、原因和执行结果 |
| 用户纠正 | 保留纠正样本，检查改进和退化 |
| 范围约束 | 当前明确限制优先于历史自主推进偏好 |

16 条包含本地用户指令来源，17 条包含固定版本仓库来源；同一条可以有两类来源。每条保留来源 ID/链接和可复用话术。按主题人工融合后入库，没有把 1,487 条原始指令逐条当作知识。

“根因与同类排查”采用循环：复现 → 根因 → 同类搜索 → 修复 → 回归 → 复审；新发现进入下一轮。收敛标准是原问题、已识别同类问题及受影响链路通过验证，约定范围内无未闭环问题。重复失败且无新证据时调整方法；外部阻塞或预算耗尽时记录剩余问题，不能将停止等同于收敛。这是 PM 的参考原则，目前不表示已经增加通用的自动收敛判定器。

## 分歧处理

- 仓库中的强制最大并行调整为当前授权允许、任务独立时采用；不覆盖当前会话的禁止委派要求。
- 全量 TDD 和仅使用 mock 的建议调整为按风险验证，区分隔离测试和真实集成证据。
- 零 DDL、固定模型/框架、部署拓扑作为项目条件，不升级成所有项目通用原则。
- 自动暂存全部文件、提交或推送不获得额外授权；遵循当前任务范围。
- 接入已有项目时不覆盖 AGENTS.md 或重新铺设项目模板。

## 存储与回用

知识包在 `src/autocoding/data/cold-start.json`；导入事件记录包版本、摘要及来源，每条初始置信度为待验证假设。导入事件证明来源，不证明效果。工作台启动时自动安装，其他直接构造 Host 的调用默认不安装；新注册项目继承工作台设置。

同版本同 ID 重复导入不新增记录；内容变化时审计更新，保留用户归档状态。已归纳主题使用独立的 `curated:` 主题空间，避免宽泛关键词将不同种子错误合并；仍受归档、过期和引用上限控制。该空间不等于跨主题语义矛盾已经完全解决。后续模型经验不会自动覆盖种子，仍需证据和冲突处理。每次最多选取 12 条有效参考，18 条均可在知识列表查看。

私有语料、来源路径映射和导入报告位于 `.local/cold-start/`，不发布。以下工具可复跑：

```powershell
.\.venv\Scripts\python.exe tools/collect_user_instructions.py
# 额外自定义存储：在上述命令追加 --transcripts D:\path\to\sessions
.\.venv\Scripts\python.exe tools/import_cold_start.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_cold_start.py
```

收集工具只更新私有语料，不自动将新文本提升为知识；需先审阅、融合和编辑知识包，再导入。导入不会恢复或重发正在运行的 Agent 任务。

后续运行中的维护已接入定期自检：有新事件时轮换检查主题，显式指向原知识组的修订进入同组治理，保留来源与旧版本；有分歧时选择采用版本。详见 [循环、维护与收尾](pm-loop-and-closure.md)。

本轮验证：冷启动 5 项、知识治理 7 项、自检 5 项、项目管理 4 项，共 21 项测试通过；前端 TypeScript/Vite 构建通过。实际账本复跑导入返回新增 0、更新 0、知识组 18、有效引用 12。未将此前的全量测试或浏览器结果当作本轮复验。
