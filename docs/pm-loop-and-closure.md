# PM 推进循环、交互学习与项目收尾

## 代码控制的推进与退出

托管任务不以 Agent 的“完成了”作为退出条件。`workflow.py` 在首轮执行结束后，依次发送两个带幂等键的检查回合：

1. 盘点剩余工作，对照任务与验收项继续完成遗漏。
2. 从架构、测试、体验角度复审，检查正常、边界、错误和恢复用例，排查同类缺陷。
3. 封闭会话输入、检查受保护文件、保存固定提交，由独立验证器执行登记的检查。

检查话术集中在 `completion.py`。两个回合均保存命令 ID 与阶段；出现未知投递、接管或超时即进入待对账状态，不重放。暂停后不派发下一回合；总超时包括复审，不因追加回合无限延长。当前多视角复审仍由原 Code Agent 执行，不冒称多个独立专家已审查。

`coordinator.py` 循环处理依赖、派发、验证与返工。已授权批次的所有任务完成后才进入集成验收，之后再次盘点剩余项并核对检查配置未改变。成功退出为 `verified_candidate`，不代表已经发布；失败检查进入返工，达到配置的尝试上限后保持未完成。无法对账、配置改变、外部阻塞不能宣称收敛。批次外剩余工作单独记录，不悄悄扩大执行范围。

以上机制保证检查阶段确实推进，不能数学证明所有业务用例完备；仍取决于任务定义和验收检查质量。追加复审会增加模型回合。更广泛的独立专家调度、需求到全部用例的覆盖判定尚未实现。

## 求助台账与举一反三

`interactions.py` 保存结构化开发问答的任务背景、问题选项、求助原因、简短决策依据、用户答案、回答者及投递状态。这里只记录可公开解释的依据，不记录隐式思维链。权限确认从既有审批表和升级事件生成记录，保留操作哈希及已有工具摘要，不另存原始命令。网页“PM 自检与知识库”可分页查看。

- 独立请求计数，状态刷新与幂等重试不增加次数；同一协议请求 ID 不能替换为另一操作。
- 重复求助按规范化文本识别，是保守指标，不代表语义完全相同，也不意味着重复求助必然错误。秘密问题不参与重复匹配。
- 回答新问题前，检索本项目最近 90 天内、已确认投递的用户答案，最多 5 条。同时带上原背景与冲突答案，不自动复制选择或跳过权限判断。
- 定期复盘学习明确表达的偏好、判断条件和例外；一次答案不能被解释成永久授权。学习目标是减少可避免的重复求助，不能压制必要澄清。
- 新问答台账从功能接入后开始记录；旧问答不会被猜测补齐求助次数。权限升级事件可追溯既有记录。终端自由文本、站外聊天尚未纳入统计。

接口：`GET /api/v1/projects/{id}/pm/interactions?offset=0&limit=25`，受现有项目 Owner 认证保护。

## 冷启动后的知识维护

有新活动时，定期自检每轮轮换最多 8 个知识主题，包括冷启动条目和后续经验。结合真实事件检查准确性、适用条件、缺口、重复、冲突与过时内容；要求专业、简洁、可执行，而不是无依据改写。

模型修订必须指向本轮提供的知识组并引用实际事件。服务端检查目标修订摘要，将候选放回原主题，保留旧条目和来源；同主题分歧沿用现有选择机制处理。没有证据不刷新为“新经验”，没有模型额度时保留待处理状态和退避记录。维护不自动修改程序控制流、权限或验收规则。

## 项目整体复盘与收尾报告

批次集成验收通过后，`closure.py` 检查项目所有登记任务均为 done，且不存在未处理的问答/审批投递，生成一次确定性事实复盘。只完成部分任务时不生成项目级收尾报告；报告生成失败不回滚已成立的集成验证结果，可通过网页重试。

报告内容包括：任务与验收状态、候选提交及集成报告摘要、历次返工或运行异常、失败检查及后续同任务验证结果、重复失败模式、已记录问答和求助统计、经验教训与结论边界。运行异常不直接叫作产品 bug；后续通过记录不直接证明根因永久消除。集成证据仅覆盖所列批次，不能声称所有历史提交都已合并。

报告与收尾经验在一个事务中写入项目 SQLite 账本；以批次 ID 幂等，保留生成时快照。经验初步由代码根据事实归纳，标记非模型生成；之后定期自检将报告作为证据继续提炼，因此模型暂时不可用也能保存可查询的收尾事实。新工作不会改变旧报告，后续经验证的批次可以产生新报告。

系统审查后强化了收尾条件：必须验证持久批次、集成工件摘要与审计事件，并且集成工件的任务版本覆盖当前全部项目任务。最后一个增量批次会整合此前已完成提交及检查，不执行未选任务。旧报告仍可查询，但会标记任务快照是否与当前项目一致，不能用旧报告替代新一轮验收。

网页该项目空间的“项目收尾复盘与报告”支持查看、关键词筛选和生成/重试，展示最近 50 份报告。报告不意味着部署完成。接口：

- `GET /api/v1/projects/{id}/pm/closures`
- `POST /api/v1/projects/{id}/pm/closures`，需要 Owner 认证及幂等键。

真正的因果根因分析、代码级 bugfix 差异解释、独立专家评审质量及长期学习收益仍需真实项目证据，不由报告生成成功推断。

## 本轮验证

全量 220 项 Python 测试通过，覆盖重复请求、用户回答回用、冲突答案保留、过期和秘密排除、冷启动修订归组、复审失败阻止提交、自动收尾及重启后的报告读取。前端构建通过，Edge 项目设置和收尾报告查询测试通过。模型判断使用替身；本轮未重跑真实模型端到端项目开发。

最后增加长任务背景的约束变化回归，交互测试 6 项通过：展示文本可以截断，背景是否相同按完整摘要比较。当前测试总数为 221；该新增项使用定向回归验证，未再次运行全量。
